Engineering

The work that happens before the interface.

Anyone can list technologies. This page is about the connective tissue — how systems are shaped, deployed, debugged and secured — and each capability is connected to projects where it's actually exercised. No fictional pipelines, no claims of stacks I haven't run.

Application architecture

Structure before surface: typed document models, state machines for flows, and features composed as projections of one data model. I design the shape of the data first and let the interface follow.

  • Order of Service
  • Developer Portfolio

API design & integration

Resource modelling, honest status codes, and boundaries that don't leak internals. On the consuming side: provider adapters, retries with backoff, and failure paths designed as carefully as the happy path.

  • Verify Hub
  • Media Storage API
  • Miro

Database design & data management

Ledgers over balances, evidence over verdicts. Schema-first thinking: what the database records decides what the system can honestly claim, so I spend real time on that layer before writing interfaces.

  • Terrific Bank
  • DataGuard

Linux development environments

Linux as daily driver and lab — users, permissions, processes, logs, and the shell habits that make remote operation feel local. My bots, tools and servers all live here first.

  • Self-Hosted Infrastructure
  • Desktop Voice AI

Containerization & deployment

Docker for isolation, Coolify for orchestration: applications deploy from GitHub into containers behind a managed proxy, with environment configuration kept out of application code.

  • Coolify Deployment
  • Media Storage API

Cloud server management

Ubuntu instances on AWS EC2, operated over key-based SSH. Every open port is a decision; every change is verified layer by layer — locally, through the security group, then from outside.

  • AWS EC2 Deployment

Domain & DNS configuration

Registrars, records, resolvers and propagation — configured by hand and debugged in a fixed order, because DNS is where impatience goes to break things that were quietly working.

  • Coolify Deployment

Troubleshooting & debugging

Logs before restarts; one variable at a time; a fixed diagnostic order from DNS to proxy to container to application. The skill I practice most, because infrastructure teaches it daily.

  • Coolify Deployment
  • AWS EC2 Deployment

Security-conscious development

Validation at the boundary, least exposure by default, and reports that never overstate scope. My security study and my build practice reinforce each other — the contact form on this site is spam-protected for the same reason my inspection tools don't over-claim.

  • Verify Hub
  • Web Intelligence Platform

Automation & operational tooling

Scripts and bots that absorb repetition without absorbing responsibility: link pipelines, tunnel utilities, notification providers, and CLIs that make capable engines pleasant to drive.

  • LinkLens
  • Tunnel Sharing Utility
  • Alchemist

The environment

The stack I run, end to end.

A simplified map of my self-hosted environment: deploys flow from GitHub through Coolify on an Ubuntu host; requests arrive through a reverse proxy into application containers backed by PostgreSQL and Redis; I operate the whole thing over SSH, and a Cloudflare Tunnel exposes local work when something needs sharing. Drawn from practice — the documented deployments, not an aspirational architecture.

What this diagram deliberately doesn't show: CI pipelines I haven't built, monitoring I haven't wired, or redundancy I don't run. Those are on the infrastructure roadmap. The projects page keeps the record honest about what exists today.
